# Tools

In this example we use the `LLMToolsClient` (`platform.tools`) to work with the Gogi tool registry. Tools are
functions a model can call, such as looking up the weather. Registering them on the platform lets agents
discover them, validate their arguments and execute them through a single interface, with rate limits,
execution limits and costs managed centrally.

| File            | What it does                                                                                     |
|-----------------|--------------------------------------------------------------------------------------------------|
| `example_6.py`  | Registers a `get_weather` tool, discovers, validates and executes it (synchronously and asynchronously), and registers an external MCP server |

## Prerequisites

- The Gogi platform running, with the gateway on `localhost:50051`

The tool endpoint (`weather.example.com`) and the MCP server (`mcp.example.com`) are placeholders; replace
them with real services to get real results.

## Running the example

```bash
python examples/intro/example_6/example_6.py
```

## Walkthrough

### 1. Register a tool

An `LLMToolServiceDefinition` describes the tool:

| Field              | Meaning                                                                                       |
|--------------------|-----------------------------------------------------------------------------------------------|
| `name`, `version`, `owner`, `description` | Identify and describe the tool. The description tells the model what the tool does |
| `parameters_json`  | JSON schema of the tool's arguments (here a required `city` string)                           |
| `returns_json`     | JSON schema of the tool's result (here `temperature_c`)                                       |
| `behavior`         | `LLMToolBehavior`: whether the tool is read-only and idempotent, and its typical latency      |
| `rate_limits`      | `LLMRateLimits`: requests per minute, per session and per day                                 |
| `cost`             | `LLMCostMetadata`: estimated cost per call and billing category                               |
| `capabilities`, `tags` | Labels used to discover the tool                                                         |
| `endpoint`         | Where the tool is served                                                                      |
| `execution_limits` | `LLMExecutionLimits`: timeout and retries                                                     |

`platform.tools.register_tool(request=LLMRegisterToolRequest(tool=tool))` adds it to the registry.

### 2. Discover tools

`discover_tools(request=LLMDiscoverToolsRequest(...))` finds tools by namespace, capability or tag. The
example looks for read-only tools with the `weather.read` capability.

### 3. Validate the arguments

`validate_tool(request=LLMValidateToolRequest(...))` checks arguments against the tool's parameter schema
before calling it, so invalid arguments generated by a model are caught early.

### 4. Execute the tool

- `execute_tool(...)` runs the tool synchronously and returns its result
- `execute_tool_async(...)` starts a long-running tool and returns a `task_id`;
  `get_task(request=LLMGetTaskRequest(task_id=...))` polls for the result

### 5. Register an MCP server

`register_mcp_server(request=LLMRegisterMcpServerRequest(...))` registers an external MCP server. Its tools are
imported into the registry under the given namespace. Policy and rate limit overrides apply to all of them;
the example requires confirmation before any of the server's tools runs and limits them to 30 requests per
minute.
